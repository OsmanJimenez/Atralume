# Stepper

Thin recipe over Taiga [`TuiStepper`](https://taiga-ui.dev/navigation/stepper): `atr-stepper` hosts `tui-stepper`, headers are `button[tuiStep]`, and `atr-step` projects the active content panel.

Atralume does **not** ship a linear/`AbstractControl` focus engine. Gate Next yourself (for example with form validity). `atrStepperNext` / `atrStepperPrevious` remain thin click helpers. Use `selected`, `next()`, `previous()`, and `reset()` to drive the index.

## Import, composition and values

Import from `@atralume/angular/stepper`. Project `atr-step` children with a `label` and optional `stepState` / `icon` / `disabled`. Content templates render only for the active step. Bind navigation Button `disabled` to your own rules plus `canNext` / `canPrevious` when useful.

## Keyboard and accessibility

Taiga owns header arrow-key focus. Stepper uses labelled regions and `aria-current="step"` rather than a tab list. Completion and error states use `stepState` (`normal` | `pass` | `error`) with Taiga’s visual treatment. Test the final application with assistive technology.

## Themes, glass and tokens

Import `@atralume/angular/styles/theme.css` once. Customize `--atr-comp-stepper-*` tokens for the content panel. Light, Dark, NestedTheme, RTL and ConsumerOverride preserve the same API.

## Common mistakes

Do not treat a visited step as completed — set `stepState="pass"` (or your own marker) explicitly. Do not expect the stepper to validate forms; keep that in the consumer.
