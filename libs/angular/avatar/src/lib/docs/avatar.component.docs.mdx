# Avatar

Use an image, explicit initials, a name, or a generic fallback for identity. Image errors fall back once per source; changing src permits a new attempt. Initials use the first Unicode code point of the first and last whitespace-separated name segments, at most two, or the first two code points of explicit initials. Combining marks and complex grapheme clusters may need explicit initials. Supply alt when this is the only identifier; use alt="" when an adjacent name provides the same information. The host owns the accessible name and the internal image is decorative. Fixed CSS dimensions and object-fit prevent layout shift; loading defaults to lazy.

## Import and minimum example

import {

Keep names meaningful, preserve visible keyboard focus, and check your application at 200% zoom and in forced colors. Automated axe checks run at error level; review assistive technology and real backgrounds manually as well.

## Customization and component tokens

Functional variants are stable inputs; component tokens control visual details. A theme supplies semantic color decisions, a surface supplies the background context, and an instance override changes one composition. Import `@atralume/angular/styles/theme.css` once, including for directive styles. Do not create CSS-valued inputs.

The public token manifest at `@atralume/angular/styles/tokens.json` lists every token. This atom uses the `--atr-comp-avatar-*` namespace, including color, size or spacing, shape and motion where applicable.

```css
.my-example {
  --atr-comp-avatar-rounded-shape: 1rem;
}
```

Overrides inherit globally, through nested themes and surfaces, or from a consumer class. Specific appearance colors can be overridden through appearance-specific tokens documented in the manifest; defaults resolve from system tokens.

Light, dark and system scopes are supported, including nested scopes. Standard, elevated, transparent and glass surfaces share the same semantic color contract. Glass uses the existing backdrop and opaque fallback; atoms do not apply their own backdrop filter. Verify contrast against the final composited background.

## Common mistakes

Avoid replacing native semantics, encoding information by color alone, removing accessible names, or relying on a tooltip for a label. Do not import internal paths or include Storybook in the application runtime. Use the exported harness for observable host state.
