# Autocomplete

Autocomplete composes editable Combobox, Listbox and Option. query is controlled and emits queryChange. With filterOptions=false the consumer supplies remote suggestions and owns debounce, cancellation and caching. minimumCharacters controls when suggestions are eligible. mode=automatic activates the first suggestion; manual mode waits for navigation. Inline text completion is not implemented.

Taiga UI note: evaluated against `TuiComboBox`. Atralume Autocomplete keeps the
controlled `query`, remote `filterOptions=false` contract, and listbox overlay
and is retained as an exception.

## Import and composition

Import from `@atralume/angular/autocomplete`. The Default and Keyboard examples are executable compositions. Every action uses the existing Button or IconButton; panels share the existing theme and overlay engine. Custom option templates receive the typed option, its value and selected state.

## Forms and values

Select, Combobox and Autocomplete support Reactive Forms, ngModel and the public Signal Forms value-control contract. Use one binding strategy per instance. Null represents no selection, and multiple selection uses an array. External writes do not emit a form change callback. Blur reports touched; disabled and readonly block user commits. Business validation and error messages belong to the consumer. Listbox is a selection primitive, not a CVA; Popover and Command Palette do not represent form values.

## Loading, empty, error and async

The consumer provides options, loading and loadError. No component performs HTTP requests or owns a backend cache. Empty and loading content have status semantics. Keep result announcements concise and stable. Option IDs must remain unique and stable as results change.

## Keyboard and accessibility

Provide visible labels. Arrow keys navigate options, Enter confirms and Escape closes without committing navigation. Tab closes without trapping the combobox; popup DOM focus stays on its input or trigger. Select-only typeahead is distinct from editable text input. Read the Keyboard story and test the resulting application with assistive technology.

## Themes, glass, tokens and consumer overrides

Import `@atralume/angular/styles/theme.css` once. Use `--atr-comp-autocomplete-*` and shared `--atr-comp-selection-option-*` / `--atr-comp-selection-panel-*` tokens. Portals inherit the trigger theme, surface, density, direction and public overrides. Light, Dark, Glass, NestedTheme and RTL show the same component in different contexts. Glass examples include a visible background; forced colors uses an opaque fallback.

## Responsive, SSR and virtualization

Panels have viewport limits and collision fallback. SSR renders the closed control and does not create browser overlays. Stable IDs support server/client consistency; hydration requires integration verification. LargeDataset uses ordinary rendering. CDK virtualization is not enabled in these examples: recycled options require additional active-descendant and scroll coordination, so this implementation does not promise virtualized accessibility or dynamic row-height support.

## Common mistakes

Do not use Menu for selecting a form value, put interactive descendants inside options, use array indices as remote option identity, or attach both ngModel and formControl. Consumers own filtering policy, remote data and business state.
